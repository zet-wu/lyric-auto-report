# 日语自动注音准确率

当前固定版本 Studio 在 11 首歌曲中，845/894 个共同正文片段的读音与人工 Ruby 完全匹配，准确率为 94.52%；400/449 个纯日语参考行整行匹配，准确率为 89.09%。正文注音与人工参考的差异主要涉及上下文选读、数字、复合词和歌曲指定读音。

## 数据与计分

测试使用 11 首主组歌曲的 478 行、4058 个原始正文分段。正文从 TTML 提取，清除 XML 排版的换行、回车和制表符，保留普通空格。读音方法只接收正文；原始 Ruby 单独作为评分参考。源 TTML 保持原样。

各工具分词不同，评分采用原始正文分段与全部方法的共同边界：对不共有的边界合并，比较同一正文范围内的完整读音。主表包含 894 个含汉字且参考为假名的共同片段；440 个无汉字片段和 11 个参考含非假名的片段另存排除清单。共同片段可以包含多个词，因此该指标称为片段准确率。整行指标采用参考全部为假名的 449 行，其余 29 行排除。

归一化使用 NFKC、片假名转平假名、去除标点与空白；保留小假名、长音符和助词拼写。空输出或残留汉字、拉丁字母仍计为错误。CER 为编辑距离总和除以参考假名字符数；宏平均对歌曲等权。

该评分衡量与现有人工 Ruby 的书写一致性。Timing、OpenJTalk 的发音前端会输出「わ／お／ー」等形式，人工 Ruby 中的「は／を／う」等写法因此可能计为不匹配。表中保留原生输出，这一差异不能直接解释为声学发音错误。歌曲指定的特殊读音也以原标注为准。

## 方法如何生成读音

| 方法 | 实现与本次调用 |
| --- | --- |
| Studio | Sudachi C 选读；JmdictFurigana 按词面与已选读音拆分注音。细分回退需与所选读音重组一致。固定源码提交为 `87b96db`。 |
| Sudachi | 直接读取 C 模式的 reading_form，作为 Studio 增补处理的对照。 |
| MiliKara | 日语 rule_segments 使用 MeCab／UniDic，再处理片段与读音单元。本次显式使用已下载的 UniDic；另单列 pykakasi 回退路径。 |
| Timing | UniDic 分词，结合数字、借词及发音覆盖规则，取规则提供的首选发音。 |
| OpenJTalk | pyopenjtalk 0.4.1 的文本前端，使用固定的 1.11 词典，输出节点发音。 |
| LLM 直接注音 | 读取整首歌词上下文，为输入分段生成假名。 |
| LLM 修正候选 | 同时读取正文与 Studio 候选，修正读音后按相同分段输出。 |

MiliKara 的 [AI 注音提示](https://github.com/BilyHurington/MiliKara/blob/ff2d2f54706ecb140bc5b275037eff64187ef6ef/kara_align/reading/ai.py)提供正文、行 ID 和 current_segments，允许修正未锁定片段的分词与读音；[调用层](https://github.com/BilyHurington/MiliKara/blob/ff2d2f54706ecb140bc5b275037eff64187ef6ef/kara_align/reading/llm.py)支持 CLI 或 API。Timing 有[纯文本 LLM](https://github.com/Zennmn/Timing/blob/3a16732e9525e11cc3dc2b5aad10c12be73abb8f/timing/llm_text.py)、音频直接处理和外部结果导入路径。

本次 LLM 条件统一提示和候选来源，由 `gpt-6.1-terra`、`gpt-6-luna` 各一个独立子代理模拟，推理强度为 high。结果按模型和条件分别保存。它们评估直接生成与候选修正两种用法；MiliKara 和 Timing 原生 LLM 服务及音频输入路径可作为后续独立比较。

每个代理先直接注音，再在同一会话中修正 Studio 候选；输入排版修正后在各自会话中统一刷新输出。代理可以使用工具序列化和检查自己的答案，未提供参考读音、音频、时间、评分或另一模型的结果。这里是每条件一份代理模拟输出，修正条件保留先前上下文。公共提示要求保留已有假名拼写和拉丁正文；含人工外语转写的片段因此可能失配。

## 错误与应用

Studio 的「私→わたくし」与参考「わたし」、「一歩→いちほ」与参考「いっぽ」、数字「100万」的逐字读法体现了上下文和复合词处理问题。参考中的「命運→うんめい」「決闘者→でゅえりすと」「切符→ちけっと」属于歌曲指定读音，纯文本的常规选读可能与实际演唱不同。

Terra 修正候选为 873/894（97.65%），Luna 为 871/894（97.43%），分别比 Studio 多匹配 28 和 26 个片段。直接注音分别为 870/894 和 776/894，Luna 在本组更依赖候选。两种模型应分别按实际输出判断；一次代理模拟不足以估计重复生成的稳定性。Studio 可以优先处理数字与复合词，并把上下文歧义和指定读音提供给用户确认；候选修正适合作为额外注音入口。

本报告只评价读音准确率。使用人工读音的对齐与异常行重算见[独立报告](local-refinement.md)。
