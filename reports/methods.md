# 测试集与评价方法

主比较包含 12 首日语歌曲。完整数据集为 14 段录音、15 份人工 TTML；日语／粤语混合歌曲及潮汕话转写另作诊断，不混入日语主表。文件、固定编号及哈希见[测试集](../datasets/README.md)。

## 产品比较

[八条路线报告](comparison.md)比较 Lazulite Studio + NextFire、Lazulite Studio + MMS_FA、MiliKara、Timing、SUG + NextFire、SUG + MMS_FA、yohane 和 FA-Kara。NextFire 指 `NextFire/mms-300m-ForcedAligner-karaoke-ja-Latn`。

| 组别 | 读音输入 | 人声输入 | 参与路线 |
| --- | --- | --- | --- |
| G1 | 人工读音 | 各自分离器 | 8 条 |
| G2 | 人工读音 | 统一 BS Karaoke | 8 条 |
| G3 | 各工具自动注音 | 各自分离器 | 前 6 条 |

Lazulite Studio NextFire 关闭智能延长；Lazulite Studio MMS_FA 开启智能延长。两者均关闭间隙合并。SUG 使用 UVR-MDX-NET-Inst_HQ_3；MiliKara 使用原生 MelBand RoFormer 默认权重；yohane 使用原生 HybridDemucs；Timing 使用 BS Karaoke。FA-Kara 不提供分离器，以外部 BS Karaoke 人声作为输入，因此 G1、G2 共用同一次结果。

输入不带人工起止时间、行窗口或行首提示。人工组保留人工读音；格式转换可合并接口无法独立表达的长音符、连接英文词片段，不能根据参考时间改变输入。自动组只保留逐行正文，重新执行各工具的分词和注音。MiliKara 原生异常行重试可能选择原曲，保留该行为并记录最终采用的音轨。

## 评分

每组分别给出两张主表。正文表只取本组全部路线与人工标注共同支持的正文边界；G1、G2、G3 各自构造分区。区间时间取同一正文范围内有效时间的最小起点和最大终点。只评价含日语文字的区间；英文仍保留在完整目标中。整曲失败及整行无有效时间的占位输出不限制其他路线的分区，但该路线仍保留全部参考分母。正文表的合并数是共同分区中被合并掉的原正文内部边界数。

读音表固定使用人工标注的 5370 个日语叶级单元：有 Ruby（正文上的读音标注）时取最细标注片段，否则取日语正文单元；独立长音符保留。各路线读取最终采用或导出的独立读音时间。工具把多个参考单元合成一个、未给出内部边界时，受影响的参考单元全部计缺失，分母不减少；单列“合并边界数”和“涉及单元数”。例如“ぜ／っ”输出为“ぜっ”，记 1 个合并边界、2 个缺失单元。合并数按文本结构判断，与时间误差无关。

读音对应先以共同正文范围作锚点，在范围内匹配读音。假名统一为平假名、NFKC 规范化并去除非读音标点；yohane 使用实际输入时的逐单元罗马字。读音字符串存在差异时采用最小编辑距离，仅使用所有最优对应方案一致的内部边界；共同正文范围的外端点由正文位置确定。同一正文范围只有一个原生时间区间时，直接将它识别为整体覆盖，按参考内部边界统计合并，不因读音文字不同改记为映射缺失。对应不唯一或没有读音输入的项目记为读音映射缺失。输出只有汉字整体时间时，以其正文覆盖范围对应整段人工读音，不猜词内边界。多个更细的原生单元可合成一个参考单元，但不插值制造时间戳。

Lazulite Studio、MiliKara 和带 Ruby 的 SUG 输出直接读取其读音单元；Timing 使用最终单元及其读音字段。SUG 读取 .sug 项目中全部已保存的节奏点，相邻点构成最小区间，句末用保存的句末点结束；带 Ruby 时按分段索引对应。自动生成的读音不会写回工程，部分汉字在 .sug 中也只有一个节奏点，按该字整体覆盖处理。原生采用命令产生的结构点同样保留，评分程序不另外插值。FA-Kara 读取 ASS 的注音与续接标记，yohane 读取 ASS 的罗马字音节，并按卡拉 OK 时值累计时间。合并缺失、读音映射缺失、无效时间和整曲失败分别保存；读音映射缺失不是独立的错读率。

100 ms、200 ms 命中要求预测时长为正，起点与终点绝对误差同时不超过阈值。主表给出命中数及占全部目标的比例；歌曲等权的宏平均在汇总 JSON 中另列。缺失、无效时间和仅供人工复核的整句占位结果均计为未命中。

MAE（Mean Absolute Error，平均绝对误差）与绝对误差 P95（第 95 百分位数）分别报告起点和终点，单位 ms，只使用有效预测。缺失数同时列出。超过 1 s 误差项按起点或终点至少一端超过 1 s 计数，缺失不混入此项。

评分使用产品最终采用或导出的时间戳：Lazulite Studio 前端采用后的文档、MiliKara 原生 alignment 导出、Timing 最终单元、SUG 保存并重新加载的 .sug 项目、yohane ASS，以及 FA-Kara 的原生 ASS 导出。yohane 与 FA-Kara 的 ASS 会改变部分尾点；按导出后的卡拉 OK 时值累计时间，不能以模型或导出前的中间尾点替代。Lazulite Studio 另按原标注的叶级单元报告细项；叶级单元是有注音时的最细读音片段，否则为正文单元。

## 叠唱

背景歌词不进入目标链和评分分母，背景声音保留在音频中。人声分离器是否保留或抑制叠唱属于各自路线的实际行为。另将参考主歌词区间与背景歌词区间有交集的项目汇总，并单列 s15。这里评价的是叠唱干扰下的主歌词，不是背景声部对齐能力。

## 独立自动注音范围

[自动注音报告](auto-reading.md)使用 s01–s10、s12、s15 共 12 首日语主组，另列 s11 前 10 行日语部分。SUG WinRT 自动注音实验在独立 Windows 环境中进行，其结果与原 Linux Sudachi 回退结果分列，其他六种本地方法与 gpt-6.1-terra 直接注音、修正 Lazulite Studio 两种条件保留原预测。对齐实验 G3 仍使用 12 首主组及原 Linux 结果，未采用此次 WinRT 注音。

## 模块诊断与资源

后端、窗口、分离器、解码机制和局部重算仍以各自报告中的固定输入协议比较。core 指活动检测得到的核心人声区间；拼接移除区间之间的音频，并在对齐后映射回原曲。人工行窗口仅用于明确标记的条件诊断，不进入八路线产品主表。CTC（Connectionist Temporal Classification，连接时序分类）表示将模型帧概率与给定歌词匹配的对齐路径。

全部声学推理与人声分离使用 GPU。质量实验允许并行，其日志耗时不作为公平速度排名；资源测量单独串行执行。对齐准确率不能替代有干净人声真值的分离质量评价。

源码、输入、模型与环境分别固定在配置清单和结果元数据中；[复现说明](reproduce.md)给出运行与独立评分入口。报告仅呈现本轮固定版本的最新结果。
