# 日语歌词自动注音与词典覆盖准确率比较

由于 `NextFire` 与 `MMS_FA` 等对齐模型接收拉丁字母（罗马字或音素）序列作为文本输入，在对没有自带注音的日语纯文本歌词进行自动打轴（如 [九条路线对齐比较](comparison.md) 中的 G3 组）前，必须先把歌词里的日语汉字词准确切分并转换成假名读音。自动注音错了多少、这 ~3%–4% 的注音差异到底会不会拖垮后续打轴，直接关系到用户在导入纯文本歌词时需不需要逐行手工校对注音。

本实验在 **20 首日语主组歌曲（`j01`–`j20`，合计 875 行正文）** 上，统一提取 **1,623 个含汉字的共同正文片段（`kanji_spans`，共 6,981 个参考假名字符）** 与 **835 行纯日语假名参考行（`japanese_lines`，排除 40 行含英文词的歌词行，共 8,778 个参考假名字符）**，对比了 **6 种本地自动注音方案** 与 **1 种大语言模型上下文复核方案（`studio-llm-corrected`）**。关于国语、粤语、潮州话的多语种词典注音准确率及其下游打轴表现，详见 [多语言与方言对齐及多语种词典评估](multilingual.md) 第 3 节。

完整逐曲指标与逐片段明细保存在 [`results/M9/summary.json`](../results/M9/summary.json) 和 [`results/M9/metrics.csv`](../results/M9/metrics.csv)。

## 核心发现

1. **在跨平台本地注音方案中，基于 `Sudachi + 复合词典拆分` 的 Lazulite Studio 与 SUG（Sudachi 模式）并列第一梯队**：
   - 在 20 首日语歌的 1,623 个含汉字片段上，**Lazulite Studio**（`SudachiPy C 模式 + JmdictFurigana`）的整段完全匹配率达 **92.98%**（1,509/1,623），片段字符错误率（CER）低至 **3.68%**（257 处字符编辑 / 6,981 参考字符）；在 835 行纯日语整行评估中，整行完全匹配率达 **86.71%**（724/835），整行 CER 仅 **2.93%**。
   - **SUG（跨平台 Sudachi 模式）** 表现与 Studio 几乎一致：含汉字片段准确率为 **92.91%**（1,508/1,623，仅差 1 个片段，CER **3.72%**），整行完全匹配率为 **86.59%**（723/835，CER **2.96%**）。
2. **Windows 原生 `WinRT` 接口（`sug-winrt`）在本地确定性方案中准确率最高，但仅限 Windows 系统可用**：
   - SUG 在 Windows 环境下调用的 `WinRTAnalyzer`（`sug-winrt`）在 1,623 个含汉字片段上达到 **93.90%**（1,524/1,623，CER **3.52%**），在 835 行整行上达到 **88.86%**（742/835，CER **2.79%**），比跨平台 `Sudachi` 路线高出 **0.92–2.15 个百分点**。
3. **基于 `UniDic Lite`、`OpenJTalk` 或发音改写规则的方案在歌词书面注音与整行匹配上差距明显**：
   - **MiliKara**（`UniDic Lite` / `pykakasi`）在含汉字片段上的准确率为 **91.13%**（1,479/1,623，CER **4.37%**），但在 835 行整行评估中回落至 **75.81%**（633/835，CER **4.19%**），主要因为复合词切分偏碎及词尾假名粘连影响了整行一致性。
   - **OpenJTalk**（`pyopenjtalk`）与 **Timing**（`g2pflow / UniDic` + 发音转写规则）的含汉字片段准确率分别为 **80.78%**（1,311/1,623，CER **7.23%**）和 **77.70%**（1,261/1,623，CER **8.02%**），整行完全匹配率分别跌至 **57.49%**（480/835，CER **6.93%**）和 **43.83%**（366/835，CER **9.02%**）。这是因为语音合成前端会将助词「は／を」与长音「う」强制改写为发音拼写「わ／お／ー」，且在未收录的歌词词汇上容易出现单字误读。
4. **引入大语言模型结合整首歌词上下文复核（`studio-llm-corrected`）可将片段准确率推至 95.19%，剩余 ~4.8% 为纯文本无法唯一确定的特殊唱法（当て字）与多音词**：
   - 在 Lazulite Studio 跨平台候选基础上引入 LLM 结合整首歌词上下文复核修正后，含汉字片段准确率提升至 **95.19%**（1,545/1,623，净修正 36 个片段，片段 CER 降至 **2.75%**），整行完全匹配率提升至 **90.42%**（755/835，整行 CER 降至 **2.24%**）。
   - 剩下的 78 个含汉字片段（4.81%）之所以仍与人工标注不同，几乎全部属于日语流行与动画歌词中特有的**特殊义读（当て字，如把汉字词按英文或另一近义词唱出）**以及**字面无法区分的多音词**（如「明日」唱作 `あした` 还是 `あす`、「未来」唱作 `みらい` 还是 `さき`）。在不结合实际演唱音频的情况下，仅靠纯文本无法从字面唯一确定歌手的实际唱法。

## 2. 自动注音对下游打轴的实际影响

结合 [九条路线对齐比较](comparison.md) 中 G1（人工读音）与 G3（自动注音）的完整打轴结果，以及 [多语言与方言对齐及多语种词典评估](multilingual.md) 中词典自动注音与人工注音的对比，可以看到：
- **93% 的日语本地注音准确率（CER ~3.7%）直接用于下游自动打轴时，共同正文边界的准确率与人工注音基本持平，细粒度假名边界也仅回落约 2–3 个百分点**：在 G3 纯文本输入下，`Lazulite Studio (BS Karaoke + NextFire)` 的共同正文双端 100 ms 命中率达 **85.56%**（G1 人工读音为 **85.32%**），人工读音边界（`n = 8,909`）双端 100 ms 命中率达 **83.70%**（G1 为 **86.59%**）。这是因为偶发的单个汉字同义异读（如 `あした` vs `あす`）通常只涉及词内 1–2 个音拍，在全局对齐中被前后准确的假名与辅音锚点限制在当前词的时间范围内，不会引发跨词或跨行的连锁偏移。
- **多语种词典（国语、粤语、潮州话）直接用于自动注音时，下游 `MMS_FA` 打轴效果同样与人工注音持平**：Studio 内置多语种词典在 5 首单语种汉字歌曲（`n=1,727`）上取得 **94.04%** 带调准确率（**94.38%** 不带调准确率），下游 `MMS_FA + 智能延长` 的双端 100 ms 命中率（Demucs **84.22%** / BS **83.64%**）与人工精调注音（**84.05%** / **83.64%**）基本一致。
